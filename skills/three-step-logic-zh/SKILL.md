# 三步邏輯 (Three-Step Logic)

## 用途

想法來的時候，總帶着一個「因為」。在它上面蓋房子之前，先讓它過一遍最簡單、卻能看出它可不可以驗證的結構：假設性三段論。第一行是條件句，第二行是你手上的情況，第三行是由此推出的結論，而四種可能的第二行裡，只有兩種推得出東西。這是張五常《經濟解釋》方法的邏輯核心：理論有用，只因它能推出一句「若甲則乙」，而乙的不出現是你看得見的。

整份東西要短。本技能是用一分鐘把想法成形，不是審查它。想法活下來、用戶要完整處理（可觀察性表、局限條件、五種形式、標價的挽救）時，交給 `refutability-audit`。

## 三步

### 第一步：寫出條件句

把想法重述成一行：**若 A，則 C。** A 是前件，即那個變了的東西；C 是後件，即應該跟着出現的東西。

兩個要求，都出自張五常。A 必須是某個可觀察事物的變動（價格、規則、費用、分數線），因為沒有變的因素解釋不了變化。C 必須是看得見或數得出的東西，因為看不到則驗不着。任何一邊若是感受、動機或態度，在旁邊寫下可觀察的替身，改用替身。

### 第二步：加上第二行，讀出第三行

用戶手上是四種第二前提之一，只有兩種允許下結論。

| 第二行 | 第三行 | 效力 | 這是什麼 |
|---|---|---|---|
| A 成立 | C 應跟着出現 | 有效 | 推測。去找 C。 |
| C 不出現 | A 不成立，或想法錯了 | 有效 | 驗證。唯一能推翻的一行。 |
| C 出現 | 關於 A 什麼也推不出 | 無效 | 證實不是證明。別的原因也產生 C。 |
| A 不成立 | 關於 C 什麼也推不出 | 無效 | 否決前事的謬誤。攻擊假設，對預測一句話也沒說。 |

指出這個想法，或對它的反駁，坐在哪一行。大多數半成品想法坐在第三行：「C 發生了，所以背後一定是我的 A。」大多數反駁坐在第四行：「你的 A 不真實，所以你的 C 不會出現。」張五常對第四行的回答：白癡隨處建油站，只有公路旁的存活，存活者與爭取最大利益的預測吻合，雖然沒有一個白癡在爭取什麼。

### 第三步：寫出殺死它的一句話

一句：**「若我在【何地、何時】看見 A 出現而 C 不出現，這想法就死了。」** 具體到兩個人都能同意它是否發生。加一行說去哪裡看。寫不出這句，這想法就還不是關於世界的想法；說明 A 還是 C 哪一邊需要先有可觀察的東西。

## 輸出

一張卡，最多一百五十字，用用戶的語言：

```
若 A 則 C：     <一行，兩邊都可觀察>
你的第二行：   <坐在表中哪一行，是否有效>
殺死它的一句： <若我看見 A 出現而 C 不出現，在……，這想法就死了。>
去哪裡看：     <一行>
狀態：         可以去驗證 ／ A 或 C 需要可觀察的替身 ／ A 需要一個真正的變動
```

想法可以驗證而用戶正在寫作時，用一句話提出可做完整審查。不主動做。

## 分寸

- 不把想法改良到超出用戶所說的。用他的話重述，然後檢查。
- 一張卡一個條件句。用戶的句子若有兩個「因為」，拆開，做兩張卡。
- 「可以去驗證」不等於「是對的」。它只表示殺死它的一句寫得出來。
- 用用戶的語言回覆。保留的用語：前件、後件、局限條件、否決前事的謬誤、看不到則驗不着。
